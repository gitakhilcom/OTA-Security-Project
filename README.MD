# Secure OTA Firmware Update and Code Signing Infrastructure

## Project Overview

This project implements a secure Over-The-Air (OTA) firmware update system for IoT devices using digital signatures. Firmware images are signed with a private key before deployment, and devices verify the signature using the corresponding public key before installation.

The goal is to ensure that only authentic and authorized firmware can be installed on target devices.

---

## Objectives

* Ensure firmware authenticity and integrity.
* Prevent unauthorized or malicious firmware installation.
* Implement secure firmware verification using public-key cryptography.
* Demonstrate a secure OTA update workflow.

## Project Workflow

1. Firmware is generated by the developer.
2. The firmware image is signed using a private RSA key.
3. The signed firmware is uploaded to the OTA server.
4. IoT devices download the firmware package.
5. Devices verify the signature using the public RSA key.
6. Installation proceeds only if verification succeeds.

## Week 2 CI/CD

### CI/CD Automation

The project includes an automated GitHub Actions workflow for firmware signing and verification.

1. CI pipeline triggers automatically when a Git tag matching `v*` is pushed.
2. The pipeline signs `firmware.bin` and generates `firmware.bin.sig` using `sign_firmware.py`.
3. The generated signature is verified using `verify_firmware.py`.
4. The workflow validates firmware integrity before artifact publication.
5. Signed firmware artifacts are uploaded and stored for deployment review.

### Workflow Steps

1. Checkout repository source code.
2. Set up Python environment.
3. Install project dependencies.
4. Generate firmware signing artifacts.
5. Sign firmware using RSA private key.
6. Verify firmware signature using RSA public key.
7. Upload signed firmware artifacts.
8. Publish CI/CD execution results.
